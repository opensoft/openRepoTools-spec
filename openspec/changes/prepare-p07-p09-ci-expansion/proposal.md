# Proposal

## Why

The P05/P06 canary passed, but its active projection admits only that exact
test-only pair. P07 adds archived fixtures and more paths; P09 changes the frozen
PostgreSQL helper and has a longer fix history. Treating them as two renamed
initial profiles would erase meaningful scope and foundation checks.

## What Changes

- Stage an explicitly disabled P07/P09 preparation manifest, separate from the
  active P05/P06 delivery policy, with exact owner-provided source bindings,
  task/path inventories, the frozen main and review/consent references.
- Add a non-gating, local Git qualification inspector and regressions for
  immutable linear history, regular file modes, empty markers, exact changed
  paths, independent members and clean ordered merge trees. Missing owner
  bindings or reviews remain pending, never inferred from old heads.
- Report the P09 foundation delta explicitly for a later reviewed activation;
  do not relax the live foundation verifier, path bounds or queue filters.
- Coordinate fresh heads and exact-head reviews with lanes 2 and 3. Open paired
  code/spec PRs only; preserve full fallback and keep P08 held.

## Capabilities

### New Capabilities

- `v13-next-cohort-preparation`: disabled, exact-head qualification of the next
  P09/P07 cohort without live omission, admission or activation authority.

### Modified Capabilities

None. The active initial-pair delivery requirements remain unchanged.

## Impact

Code changes are limited to a separate CI preparation manifest, its inspector,
targeted tests and a CI operator note. Canonical planning lives in the spec leg.
No active workflow, job, coverage baseline, classifier, delivery policy, queue,
runtime command, release workflow, setting, app access, paid plan, installed
tool, assembly pin, shared checkout or running lane changes. No live batch or
merge is authorized by preparing these PRs.
