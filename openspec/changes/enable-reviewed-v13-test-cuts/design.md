See proposal.md. This paired feature is based on feature014, not a manual
worktree. Code#100/spec#66 are reviewed source prerequisites, still unmerged at

## Goals / Non-Goals

Qualify an explicit post-P02 foundation and replace unused initial bindings
within the existing test-only scope. Do not broaden to product/fixture/control
paths, flatten dependencies, take over owner PR edits, relax test coverage or
change settings/pins/tools/releases/sessions. No live action follows from a
draft, an enabled flag alone, shadow output or a local review.

## Decisions

1. Add an optional strict foundation epoch to the trusted projection. Pin the
   exact actual landed commit and all four foundation file blobs, not a moving
   branch or generated candidate. Require P01 ancestry, epoch ancestry to base,
   exact declared blobs and no subsequent foundation-file/mode changes. Keep
   workflow/baseline and seven P01 markers frozen from original P01. Missing
   epoch preserves the original stricter freeze. A shared data-only predicate
   serves observer contract checks and delivery configuration; no observer
   classification/output becomes a grant. Reject silent re-anchoring and
   per-request 'latest main' blob discovery as authority.
2. Recognize exactly two reviewed named test-only profiles with explicit source
   identities, bounded linear histories and complete task/file inventories.
   Replace P03/P05 with P05/P06 only after actual owner data is confirmed.
   Preserve initial-profile fixture histories so original single-child/refusal
   contracts remain tested; add revised-epoch/new-pair fixtures independently.
   Do not change any workflow jobs, commands, baseline or provider pin.
3. Count separate qualification layers honestly. Use exact-head ordinary and
   reusable source CI plus the integrated staged tree for code#100 only if its
   actual owner/config landings match that tested tree. For the revised helper,
   first find any existing matching real fixture receipt. If absent, use the
   unchanged P01 smoke-driver pattern in one separate coordinator verify branch
   on the actual landed epoch, require real start/clone/SELECT1/stop/restart
   output and compare helper blobs. Keep that driver out of product source,
   deduplicate before dispatch and never run the stale-cluster sweep on user
   benches. Engine detection or the pure contract selector is not fixture proof.
4. Final policy publication and operator admission are separate. Do not set
   the working flag true or fill missing heads/epoch during draft preparation.
   At finalization require actual immutable qualification and owner readiness,
   then exact-head full/reuse/expert/bot checks and normal merges. Lane1 alone
   edits opt-in/body/base metadata and triggers fresh source events as consented;
   body edits alone do not run the opened/synchronize/reopened CI workflows.
   Coordinate a stable canary interval with lane3 without a ruleset freeze or
   interruption of an active product candidate. Use only the named manual queue.

## Risks / Trade-offs

- Owner main/candidates advance -> recheck actual trees and epoch, discard stale
  staged evidence, and coordinate a merge window rather than reset their batch.
- New epoch could become a generic escape hatch -> strict complete inventory,
  immutable actual-main ancestry, unchanged PG workflow/baseline and independent
  real fixture qualification before reviewed policy publication.
- Existing review/fast evidence may predate retarget/enablement -> require fresh
  canonical source event/base history and actual exact-head review; no synthetic
  green status, counterfeit review or forced head change.
- Initial bindings are not scalable all-work adoption -> the first accepted pair
  is one gate, with wider task-set profiles reviewed only afterwards.

## Migration Plan

Prepare tests and bounded source changes without inventing external facts.
After the normal owner landing, verify the actual epoch and source readiness;
publish only complete checked data and leave owner edits with owners. Land the
source/config through normal checks in a safe slot, verify actual main, obtain
fresh exact-head admission consent, run the two-member canary and audit its
complete artifacts/prefixes/landing. A normal reviewed false flag is rollback;
retain full fallback and no automatic retry/failure split. Wider rollout and
assembly/session adoption are separate, not implied by this initial enablement.
